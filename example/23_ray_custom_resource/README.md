# Custom Resource

## 学习目标

声明 Ray 自定义逻辑资源，并让任务只在具备该资源的节点上运行。

## 核心 API

- `ray.init(resources=...)`：为本地节点声明自定义资源。
- `@ray.remote(resources=...)`：声明任务所需资源。
- `get_assigned_resources()`：查看任务实际获得的逻辑资源。

## 实现说明

- 本地 Ray 节点声明一个名为 `accelerator_type_a` 的逻辑资源。
- 任务装饰器声明必须占用 1 单位该资源，Scheduler 只在满足条件的节点运行它。
- 任务内部读取已分配资源进行验证，明确资源声明不等于真实硬件隔离。

## 学习与复现

1. 运行基线并检查任务获得的资源字典。
2. 将节点资源容量改为 2，并行提交两个任务验证容量并发。
3. 把任务需求改为大于节点容量，使用状态工具观察 Pending 原因后终止实验。
4. 新增第二种自定义资源，验证任务必须同时满足全部需求。
5. 总结逻辑资源适合表达什么，不适合替代哪些 OS 或硬件限制。

## 运行

```bash
python example/23_ray_custom_resource/main.py
```

预期输出：

```text
scheduled
```

## 验收标准

- 任务只在自定义资源容量满足时运行。
- 任务内部能观察到实际分配的逻辑资源。
- 能解释逻辑资源约束与真实硬件隔离的区别。

## 产出

- 可独立运行的 `main.py`。
- 资源满足、容量不足和多资源组合三种实验记录。

## 注意事项

自定义资源是 Ray 调度使用的逻辑容量，不代表操作系统级隔离，也不会自动限制真实硬件使用。
