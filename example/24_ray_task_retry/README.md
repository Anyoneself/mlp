# Task Retry

## 学习目标

配置 Ray Task 在遇到指定临时异常时自动重试。

## 核心 API

- `max_retries`：任务失败后的最大重试次数。
- `retry_exceptions`：允许触发重试的应用异常类型。
- Actor：记录跨任务重试保留的尝试次数。

## 实现说明

- `AttemptTracker` Actor 保存跨重试可见的尝试次数，避免依赖可能变化的 Worker 进程内全局变量。
- `flaky_task` 首次抛出指定临时异常，装饰器只允许一次应用级重试。
- 第二次执行返回成功结果，Driver 对结果和尝试次数进行断言。

## 学习与复现

1. 运行基线并确认任务在第二次尝试成功。
2. 将 `max_retries` 改为 0，观察错误如何在 `ray.get()` 时暴露。
3. 改为不在 `retry_exceptions` 中的异常，验证它不会按当前策略重试。
4. 给任务增加模拟写入副作用，观察重试可能造成重复执行。
5. 使用请求 ID 或幂等写入重新设计副作用路径。

## 运行

```bash
python example/24_ray_task_retry/main.py
```

预期输出：

```text
succeeded on attempt 2
```

## 验收标准

- 指定临时异常触发且只触发一次重试。
- 不可重试异常或重试次数耗尽时，错误能传播到 Driver。
- 副作用路径具备明确的幂等设计。

## 产出

- 可独立运行的 `main.py`。
- 可重试、不可重试和幂等副作用实验记录。

## 注意事项

重试可能重复执行已经产生的副作用。生产任务应保持幂等，或使用唯一请求 ID、事务等机制防止重复写入。
