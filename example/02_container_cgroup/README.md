# 容器与 cgroup

**阶段：** 基础补齐  
**建议时间：** 第 1 周后半段  
**前置条件：** 完成任务 01，安装 Docker 或兼容容器运行时

## 目标

理解容器进程、Namespace、cgroup，以及 CPU 和内存限制如何作用于进程。

## 实现说明

- 使用一个容器启动脚本统一设置 CPU、内存、进程数和挂载参数，避免手工命令不一致。
- 容器内运行可控的 CPU 和内存负载，宿主机侧读取对应 cgroup 的限制值、使用量和事件计数。
- 将正常、CPU 限流和 OOM 三种场景分别记录，明确容器配置与内核观测值的对应关系。

## 学习与复现

1. 启动带 CPU、内存限制的容器。
2. 对比宿主机和容器内看到的 PID、网络接口和文件系统。
3. 查看容器对应的 cgroup 配置与资源统计。
4. 制造 CPU 竞争并观察限流。
5. 制造内存超限并记录进程退出原因。
6. 扩展实验：把 CPU 配额减半，比较 throttled 时间和任务完成时间。

## 验收标准

- 能说明容器不是虚拟机，核心隔离来自 Namespace 与 cgroup。
- 能找到容器 CPU、内存限制对应的 cgroup 文件。
- 能解释内存 OOM 与 CPU throttling 的差异。

## 产出

- `container-limits.md`：实验命令、观测数据与结论。
- 一个带明确资源限制的容器启动脚本。
