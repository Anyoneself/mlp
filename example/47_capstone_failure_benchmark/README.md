# 综合项目故障演练与压测

**阶段：** 综合项目  
**建议时间：** 第 24 周前半段  
**前置条件：** 完成任务 44-46

## 目标

用稳定负载验证节点、Worker、Actor 和模型服务故障时的性能与恢复。

## 实现说明

- `scenarios.yaml` 为每种故障定义目标选择器、前置检查、注入动作、最长持续时间和恢复动作。
- `run_experiment.sh` 先启动固定负载和监控，再执行单一故障，最后自动停止并收集结果。
- `analyze.py` 对齐请求、Pod、Ray 和 GPU 时间线，计算错误窗口与恢复时间。

## 学习与复现

1. 建立无故障性能基线。
2. 分别注入 Worker Pod、GPU Node 和 Actor 退出。
3. 记录错误率、P95/P99、恢复时间和丢失任务。
4. 在容量紧张时重复故障实验。
5. 对比直接 vLLM 与 KubeRay 架构。
6. 每次只注入一种故障，并在隔离 Namespace 检查目标后执行。
7. 扩展实验：在 50% 和 80% 基线利用率下重复同一故障。

## 验收标准

- 每次故障注入都有明确范围、停止条件和恢复步骤。
- 原始压测数据和监控时间线可关联。
- 能量化两种架构的吞吐、延迟和恢复差异。

## 产出

- 压测脚本和故障演练脚本。
- 性能与恢复对比报告。
