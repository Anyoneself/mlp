# Wait For Tasks

## 学习目标

使用 `ray.wait()` 分批获取已完成任务，避免等待全部任务结束后才开始处理结果。

## 核心 API

- `ray.wait()`：将引用分为已就绪和未就绪两组。
- `num_returns`：指定每次等待的结果数量。
- `ray.get()`：读取本轮已就绪结果。

## 实现说明

- Driver 一次提交多个不同耗时任务，并将全部引用放入 `pending`。
- 循环调用 `ray.wait(..., num_returns=1)`，每轮把引用拆成 ready 和剩余 pending。
- 只对 ready 引用调用 `ray.get()`，实现结果到达即处理，不假设固定完成顺序。

## 学习与复现

1. 先预测三个任务的理想完成顺序，再运行基线。
2. 重复运行并理解为什么分布式完成顺序不能作为正确性条件。
3. 将 `num_returns` 改为 2，观察每轮 ready 和 pending 的数量。
4. 对比 `ray.get(all_refs)`，说明增量处理对流式消费和内存的价值。
5. 增加超时参数，处理本轮没有任务就绪的分支。

## 运行

```bash
python example/22_ray_wait/main.py
```

输出包含 1、2、3，例如：

```text
[2, 3, 1]
```

## 验收标准

- Driver 使用 `ray.wait()` 增量消费结果。
- 断言只验证结果完整性，不依赖固定完成顺序。
- 能处理超时或暂时没有 ready 结果的扩展场景。

## 产出

- 可独立运行的 `main.py`。
- 不同 `num_returns` 和超时设置的行为记录。

## 注意事项

分布式任务的实际完成顺序不应作为业务正确性的前提，因此代码只验证结果集合，不验证固定顺序。
