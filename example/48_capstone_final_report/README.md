# 综合项目最终交付

**阶段：** 综合项目  
**建议时间：** 第 24 周后半段  
**前置条件：** 完成任务 44-47

## 目标

整理完整设计、代码、部署、监控、压测和复盘材料，形成可评审交付。

## 实现说明

- `final-report.md` 按需求、架构、实现、验证、结果、限制和后续计划组织，并链接原始证据。
- `reproduce.sh` 或 Makefile 只编排已验证的准备、部署、测试和清理命令，不隐藏必要参数。
- `manifest.json` 记录代码提交、镜像、模型、数据、依赖、硬件和集群版本。

## 学习与复现

1. 整理架构、容量、部署和安全设计。
2. 固化代码、配置、镜像版本和复现命令。
3. 汇总性能、成本、扩缩容和故障数据。
4. 列出已知限制、未决风险和优化优先级。
5. 按验收清单进行一次从零部署和演示。
6. 让未参与开发的人只依据 README 在新环境复现核心路径，并记录所有缺口。
7. 修正文档后再做一次 clean-room 验收，最后更新路线完成状态。

## 验收标准

- 第三方能依据文档复现核心路径。
- 关键结论有监控、日志或压测数据支撑。
- 所有凭据、内部地址和大型生成物均未提交仓库。
- `example/README.md` 中只勾选真正通过验收的任务。

## 产出

- 最终设计文档、代码和部署清单。
- Dashboard、压测报告、故障报告和后续优化列表。
